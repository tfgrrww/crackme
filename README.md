# SignalVM v2 — Reverse Engineering Challenge

**Категория:** Reverse Engineering / Crackme  
**Версия:** 2 — 2026-10-14  
**Сложность:** Hard  
**Платформа:** Linux x86_64 ELF  
**Формат флага:** `FLAG{...}`  

---

## 📜 Описание челленджа

После первого исследования неизвестного ELF-файла его автор переработал механизм авторизации. Старые ключи больше не подходят, а прямое обращение цепочки преобразований не открывает доступ.

Ваша задача — исследовать исполняемый файл `crackme`, восстановить механизм проверки и извлечь **цельный статичный секретный ключ**.

Репозиторий намеренно содержит только готовый артефакт. Исходники генератора и эталонное решение не публикуются.

---

## 🎯 Правила и условия

1. Секретный ключ — **единая фиксированная строка**, не зависящая от времени, сети, PID, ASLR или компьютера участника.
2. Длина ключа — **32 ASCII-байта**. Формат: `FLAG{` + 26 символов из `A–Z`, `a–z`, `0–9`, `_` + `}`.
3. Программа принимает одну строку через `stdin`. Поддерживаются окончания LF, CRLF и EOF после ключа.
4. Правильный ключ даёт сообщение:
   ```text
   [+] ACCESS GRANTED! Congratulations, reverse engineer!
   ```
   и код возврата `0`.
5. Неправильный ключ даёт сообщение об отказе и код возврата `1`.
6. Цель — найти ключ для **оригинального бинарника**. Патч сообщения или условного перехода не является решением.
7. Все данные, необходимые для решения, находятся в ELF. Внешние сервисы, SSH-ключи и криптографический перебор случайного флага не требуются.

## 🚀 Быстрый старт

### Проверка целостности

```bash
sha256sum -c sha256sum.txt
```

### Linux x86_64

```bash
chmod +x ./crackme
./crackme
```

### Docker

```bash
docker compose up -d --build
nc localhost 1337
```

Контейнер рассчитан на `linux/amd64`. На ARM/macOS требуется поддержка эмуляции этой платформы в Docker.

Остановить сервис:

```bash
docker compose down
```

## 🛠️ Инструменты

- Ghidra, IDA, Binary Ninja, radare2 / rizin;
- GDB, трассировка, собственный эмулятор или декодер;
- SMT/SAT-инструменты при необходимости;
- `readelf`, `objdump`, `strings`.

Обратите внимание: `SIGILL` используется намеренно. Остановка отладчика на этом сигнале сама по себе не означает повреждение ELF. Для продолжения исполнения в GDB можно использовать:

```text
handle SIGILL nostop noprint pass
```

## ⚠️ Примечания

- Флаг v1 не принимается в v2.
- Публичный бинарник не содержит флаг открытым текстом.
- Проверка детерминирована; скорость отладчика и таймер процессора не влияют на правильность ключа.
- Изучать и запускать неизвестные исполняемые файлы рекомендуется в изолированной среде.
